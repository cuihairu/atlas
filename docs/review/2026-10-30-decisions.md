## 1. API 稳定化与 v1.0

**现状**:契约冻结前的仓内准备已交付——REST 全部 52 条路由与 gRPC 全部 5 服务 23 方法已 pin 进
测试(`internal/httpapi/surface_test.go` 读注册点比对金清单、`internal/grpc/surface_test.go` 枚举
编译内 proto 描述符比对金清单),加/删/改契约不有意识更新清单即测试红,冻结从"靠自觉"变成
"diff 有守卫"。BLOCKED 两点:① 冻结决策与发版须用户拍板;② 缺生产环境部署验证实证
(取证:`find deploy -type f` = 15 个,全是 compose/HA/k8s 演示 manifest + 演练脚本,部署记录检索
0 命中;`git tag -l` 仅 v0.1.0–v0.1.4,均早于 2026-10-11 发版红线)。

### 推荐决策
**暂缓** — 契约冻结与发版是产品级决策,须用户拍板,且缺生产部署验证实证;两者均不代决。

### 理由
- **成本**:仓内可做项已全部做完(契约 pin、门禁全绿),继续推进无增量;真正的前置是生产环境验证,不是更多代码。
- **收益**:只有用户能判断"生产验证充分"并给出冻结/发版决定;代决不能替代用户对产品契约稳定性的责任。
- **风险(红线)**:按 2026-10-11 版本红线,未经验收测试的二进制不得当正式版本对外,且版本号只能由用户手动给出并触发;擅自冻结会锁死仍在演进的 REST/gRPC 契约。
- **风险(实证)**:无生产部署记录,却宣称"验证充分"即属虚构证据;审计口径要求证据可查。

### 立即执行动作
无。此项需用户输入:冻结/发版决策 + 生产环境部署验证实证(或用户点名可部署的生产机器)。

### 明确不做 / 延后什么
- 不自行冻结契约、不打 v1.0 tag、不建正式 GitHub Release(红线)。
- 不把仓内契约 pin 的测试绿当成"生产验证"——两者是不同证据面。
- 不 bump 版本号。

## 2. 生产形状压测与长稳观测(100/1k/5k 全规模验收 + ≥24h 浸泡 + 演练折入)

**现状**:设计定稿 `docs/performance.md §9`(代表性拓扑 `deploy/docker-compose.ha.yaml`、节拍形
负载模型、规模点 100/1k/5k、验收口径全文 §9)。工具链已齐:一键入口 `deploy/perf/run.sh`
(四档 plan 均 exit 0)、`soak.sh` 三件套、`loadgen` 分端点 p50/p95/p99、`soakcheck` 判读器
(覆盖度/warmup/plateau)。本地已实测:100 档、1k 档、5k 档(5k 显示盒子先饱和,ops p50 3.0s)、
两类演练(杀副本、PG 短断自愈)。BLOCKED:缺用户指定生产形状机器+排期(24h 浸泡不能落共享
演示机;候选机 docker100 本机无 SSH key——`Permission denied (publickey)`,hermes 唯一 peer
win-worker 是 Windows,承接不了 Linux PG+Redis+HAProxy 栈)。

### 推荐决策
**暂缓** — 验收必须落在生产形状机器上(§9 口径),机器与排期属外部条件,照实列卡点;不降格验收标准。

### 理由
- **成本**:工具链已在仓内且本机三档都跑过;继续本地重复无增量,只有换机器才产生新证据。
- **收益**:生产形状真机上跑出的 p95/p99 才是 §9 验收证据;本地共享演示机的数值只能当参考,不能当验收。
- **风险(误判)**:在演示机跑 24h 浸泡会干扰他人使用,且演示机资源形状 ≠ 生产形状,测出的 plateau 不能外推;docker100 需用户提供访问,强行连会撞 `Permission denied`。
- **风险(降格)**:把本地结果当验收、把 smoke 档当全规模,属放松标准,会让"验收"二字失去意义。

### 立即执行动作
无。此项需用户输入:点名生产形状机器+排期(或提供 docker100 的 SSH key 访问)。

### 明确不做 / 延后什么
- 不在共享演示机跑 ≥24h 浸泡。
- 不把本地 100/1k/5k 数值当验收证据(仅作参考,数值已在 §9)。
- 不放松 p95/p99 门槛、不把 smoke 档当全规模验收。
